# Job Card – auto scan, fetched details, layout, keyboard (21.11.2026)

Paths are relative to `mobile\`. No new npm package, no API change and no database change. The camera (expo-camera) and OCR (Google ML Kit, `@react-native-ml-kit/text-recognition`) are the ones the app already uses.

## What changed

| File | Change |
|---|---|
| `src\components\ChassisScanButton.tsx` | CHANGED. The live scan reads **only the text inside the guide box**, so other numbers in view are ignored. A number is accepted when it is the best reading in **2 of the last 3 frames** (was: 2 frames in a row, which two numbers in view could block for ever). A confident reading is **handed back automatically** after a 0.7 s "✓ found" screen, with no "Find vehicle" tap; "Not correct? Edit" stays available. An unsure reading or no reading still opens the check / type box. New green corner guide; 46 px camera button. |
| `src\utils\vehicleIdOcr.ts` | ADDED functions only: `restrictToRegion`, `screenRectToPhoto`, `createVoteTracker`, `isConfident`. Existing functions are unchanged. |
| `src\utils\vehicleIdOcr.selftest.ts` | 8 new checks (guide box, screen→photo mapping, voting, confidence). |
| `src\screens\JobCardWizardScreen.tsx` | (1) A scan now runs the lookup **at once** (this dealer). (2) If the number is not found for this dealer, the **all-dealer lookup runs by itself** and the vehicle is applied. The same "open job card" and "This Vehicle not sold" checks apply. The "Search all dealers" button stays for a manual retry. (3) New **"Vehicle details fetched"** card in Job Card order: Vehicle → Customer → Components → Service & warranty. It shows the lookup's own values, "—" when empty, and marks a vehicle of another dealer. (4) Layout polish: card shadow, clearer labels, 46–48 px fields and buttons, content centred with a 760 px max width on tablets. Field order, validation, API calls and saving are unchanged. |
| `src\components\KeyboardSafeView.tsx` | Superseded – now only re-exports `KeyboardSafe.tsx`. **Delete it.** |

**Keyboard:** the global keyboard fix is `src\components\KeyboardSafe.tsx`, made in the same session today and already wired into `App.tsx`, every ScrollView and every Modal. It handles Android edge-to-edge without padding twice. The Job Card wizard uses it through its `ScrollView` import, so no second fix was added.

## Deploy

1. Copy the changed files into `C:\Users\priyanka.nikam\Desktop\JobCardScanner\JobCardScanner\mobile` (already done if this file is there).
2. Open a terminal there and run:
   ```
   npm install
   npx tsc --noEmit
   npx tsx src/utils/vehicleIdOcr.selftest.ts
   ```
3. **Quick test on your phone with the existing development build:** `npx expo start -c`, then open the app. The scanner and wizard changes are JavaScript only, so the installed dev build is enough for them. Expo Go does NOT contain ML Kit.
4. **APK for staff (EAS, as before):**
   ```
   npx eas build -p android --profile preview
   ```
   Download the APK from the link EAS prints. `production` and `playstore` profiles work the same way.
5. **Or build locally** (needs Android Studio / SDK):
   ```
   npx expo prebuild -p android --clean
   cd android
   .\gradlew.bat assembleRelease
   ```
   The APK is at `android\app\build\outputs\apk\release\app-release.apk`.
6. **Install:** with the phone on USB debugging, run `adb install -r <apk>`. Or copy the APK to the phone, open it and allow "Install unknown apps".
7. **Rollback:** `git checkout -- .` in `mobile\` (all changes are in git).
